## Description

A post-STT, pre-injection pipeline stage that cleans transcribed text before it reaches the active window. Three sequential processing layers handle the most common speech disfluencies: (1) a configurable filler word removal pass strips hesitation markers and discourse particles, (2) a repetition deduplicator removes consecutive duplicate phrase fragments using edit-distance comparison, and (3) a self-correction detector recognizes verbal correction commands ("delete that", "scratch that", "no wait") and triggers a rollback of recently injected text rather than injecting the command phrase itself. An optional fourth layer routes the cleaned transcript through a local Ollama model for LLM-quality prose cleanup on a non-blocking async path, replacing the already-injected text in-place if the result arrives within a configured timeout.

## User Pain

Whisper transcribes speech faithfully, which means it also faithfully transcribes everything users do not intend to say. Filler words ("um", "uh", "like", "you know"), false starts, and verbal self-corrections that are natural in speech produce awkward, unprofessional text when injected verbatim into code comments, emails, and documentation. Users currently post-process every dictated passage manually, negating much of the time savings from voice dictation. Users with speech patterns that include higher filler word density (nervous speakers, non-native speakers, users with certain speech differences) are disproportionately affected. This is a known pain point documented across Whisper-based dictation tools [EVIDENCE src-012] and is the most common feature request after streaming display [EVIDENCE src-016].

## Proposed Solution

**Module:** `src/yazses/postprocess/disfluency.py`

**Layer 1 — Filler word removal:**
```python
DEFAULT_FILLERS = {
    "en": ["um", "uh", "er", "ah", "like", "you know", "basically",
           "literally", "actually", "so", "right", "okay so", "I mean"],
    "de": ["ähm", "äh", "halt", "quasi"],
    "fr": ["euh", "ben", "genre", "quoi"],
}
```
Implementation: compile each filler into a `re.Pattern` with word-boundary anchors (`\bum\b`), case-insensitive. Apply as a single multi-pass substitution. Language detected from `config.toml [stt] language` or inferred from transcript character statistics. Configurable: users can add/remove entries via `config.toml [postprocess.fillers]`.

**Layer 2 — Repetition deduplication:**
Detects consecutive repeated phrase fragments (false starts). Algorithm:
1. Tokenize transcript into words.
2. Sliding window of 2–5 words. For each window, compute Levenshtein distance against the immediately following same-length window.
3. If distance ≤ 1 (i.e., near-identical), remove the first occurrence.
4. Example: "I want to I want to add a function" → "I want to add a function".
Uses `rapidfuzz` for Levenshtein (already available in the faster-whisper dependency tree, or add as a lightweight dep). O(N²) but N < 200 words for a typical utterance — <2ms.

**Layer 3 — Self-correction rollback:**
Command phrases that trigger rollback (configurable list):
```
"delete that", "scratch that", "no wait", "I mean", "strike that",
"cancel that", "erase that", "forget it", "disregard that"
```
When detected anywhere in the transcript:
1. Identify the correction command token position.
2. Remove all text before the correction trigger from the current utterance (the part the user is retracting).
3. Remove the correction command itself.
4. If injection has already occurred (streaming mode, cap-002), trigger a backspace-based or range-select rollback for the already-injected characters.
5. Continue injection with only the post-correction text.

**Layer 4 — Optional LLM cleanup (async):**
```toml
[postprocess.llm]
enabled = false
provider = "ollama"           # "ollama" | "llamacpp"
model = "llama3.2:1b"         # small model sufficient for text cleanup
timeout_ms = 500
prompt_template = "Clean up this transcription for injection into a code editor. Remove hesitations, fix grammar, preserve technical terms exactly. Return only the cleaned text.\n\nTranscription: {text}"
```
Flow: inject the rule-processed text immediately (zero latency), simultaneously dispatch async LLM call. If LLM responds within `timeout_ms`, perform an in-place replacement using the same range-select mechanism as cap-002. If it times out, leave the rule-processed text in place.

**Config:**
```toml
[postprocess]
enabled = true
filler_removal = true
repetition_dedup = true
self_correction = true
custom_fillers = ["basically", "right"]
```

## Feasibility Notes

**Complexity:** Low. All three rule-based layers are standard NLP primitives with no model dependencies. The LLM layer reuses the async injection infrastructure from cap-002 and is opt-in. This is the lowest-risk capability in the pipeline and can ship independently of all others.

**Dependencies:** `rapidfuzz` for Levenshtein (adds <500KB). Optional Ollama client (`ollama` Python package, ~50KB) for layer 4. No GPU, no model download required for layers 1–3.

**Risks:**
- Overly aggressive filler removal removes legitimate technical words. Mitigate: word-boundary regex anchors, and a domain-aware exclusion list (e.g., "like" is never removed if followed by a Python comparison operator character).
- Self-correction detection on partial phrases: "I mean" is also a valid dictation phrase ("I mean the function name"). Mitigate: require the phrase to appear at the start of an utterance or immediately after a pause marker in the word timestamps.
- LLM layer adds Ollama as an optional system dependency; document clearly as opt-in only.

## Success Metrics

- Filler word removal recall: ≥95% of filler words removed from a 200-utterance annotated test corpus.
- Filler word removal precision: ≤1% false positive rate (legitimate words incorrectly removed).
- Repetition dedup: ≥90% of consecutive repetitions correctly removed, zero false dedup cases in the test corpus.
- Self-correction detection: ≥95% correct rollback on 50 annotated self-correction utterances.
- Rule-based pipeline end-to-end latency: <10ms on a 4-core CPU.
- LLM layer: clean text delivered within 500ms timeout on 90th percentile utterance on a mid-range CPU running llama3.2:1b via Ollama.
