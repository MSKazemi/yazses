## Description

An opt-in voice enrollment and local model adaptation workflow that tunes Whisper's transcription accuracy for users whose speech patterns differ significantly from the training distribution. This includes users with dysarthria, stuttering, aphasia, non-native accents, voice disorders, or speech affected by neurological conditions. A guided enrollment CLI wizard records 50 phonetically diverse prompts and stores the audio locally. An overnight or user-initiated background job runs PEFT/LoRA fine-tuning of the Whisper encoder on the enrolled audio, producing a lightweight adapter that is merged into the model at daemon startup. Alongside adapter tuning, a set of configurable acoustic accommodations addresses timing and energy parameters that rule-based adaptation cannot reach.

## User Pain

Standard Whisper models are trained predominantly on clean, typical speech and perform substantially worse on atypical speech patterns [EVIDENCE src-008]. Users with dysarthria, stuttering, or strong non-native accents report word error rates 3–5x higher than typical-speech users, effectively making the product unusable for the people who most need hands-free voice input. Mainstream cloud dictation tools (Dragon, Google Voice) charge hundreds of dollars per year and require sending audio to remote servers — an unacceptable privacy and cost barrier for users who already face accessibility challenges. Voiceitt [EVIDENCE src-008] provides personalised offline recognition but targets only mobile platforms. YazSes is uniquely positioned to serve this underserved population because it is already offline, privacy-preserving, and cross-platform.

## Proposed Solution

**Enrollment wizard:**

```bash
yazses doctor --enroll-voice [--language en] [--prompts 50]
```

Flow:
1. Display 50 prompts drawn from the Harvard Sentences + ARPAbet phoneme coverage corpus (included in package data). Each prompt is 8–12 words covering all phoneme pairs.
2. For each prompt: show text, wait for hold-key press, record audio, release, play back, ask "Accept (y) / Re-record (r) / Skip (s)".
3. Accepted recordings saved to `~/.config/yazses/enrollment/<timestamp>/<prompt_id>.wav` (16kHz mono).
4. On completion: display summary statistics (mean amplitude, detected speech segments, estimated SNR), warn if any recordings appear problematic.
5. Print next step instructions: "Run `yazses adapt` to start training (estimated time: 20–60 minutes on CPU)."

**Adaptation training (`yazses adapt`):**

- Loads enrolled WAV files + ground-truth prompt texts.
- Applies `peft` library LoRA adapter targeting Whisper encoder attention layers (`q_proj`, `v_proj`), rank=8, alpha=16. [EVIDENCE src-009]
- Training loop: 3 epochs, batch size 4, AdamW, lr=3e-4, cosine schedule. All on CPU (or MPS on Apple Silicon, CUDA if available).
- Estimated duration: 20 min on a modern 8-core CPU, <5 min on Apple Silicon M2, <2 min on mid-range CUDA GPU.
- Saves adapter weights to `~/.config/yazses/adapters/<timestamp>/adapter.safetensors` (~8MB for rank-8).
- Prints WER comparison: baseline Whisper-tiny vs. adapted model on a held-out 10% of enrollment audio.

**Daemon integration:**

```python
# stt/faster_whisper.py
if config.adapter_path:
    model = WhisperModel("tiny.en", compute_type="int8")
    # Load PEFT adapter via transformers + peft, merge into encoder weights
    model = load_and_merge_adapter(model, config.adapter_path)
```

The adapter is merged (not applied at inference time) to avoid inference overhead. Merge is done once at startup; no per-utterance cost.

**Acoustic accommodations (config-driven):**

```toml
[accessibility]
# Extend silence detection window for slower speech
min_silence_duration_ms = 2000       # default: 500

# Alternative hold triggers for users who cannot sustain key press
hold_key_alternatives = ["joystick_button_1", "footpedal_left"]

# Lower noise gate for soft or breathy voices
noise_gate_threshold_rms = 0.005     # default: 0.02

# Larger audio chunks for lower-energy speech onset
chunk_size_samples = 9600            # default: 4800

# Stutter handling: skip audio segments shorter than this
min_segment_duration_ms = 80         # filters out very brief glottal events
```

**Footpedal / joystick support:** New evdev-based `HotkeyBackend` variant reads from `/dev/input/event*` filtered by device name. Configured as `hold_key = "evdev:Infinity IN-USB-2"` or `hold_key = "joystick:0:button:3"`.

**Privacy guarantee:** All audio and adapter weights remain in `~/.config/yazses/`. The wizard explicitly states this and `yazses doctor` can audit it.

## Feasibility Notes

**Complexity:** High. LoRA fine-tuning on CPU is computationally feasible but requires careful memory management — Whisper-tiny has 39M parameters; encoder-only LoRA at rank 8 adds ~200K trainable parameters, manageable on 4GB RAM. The main technical risk is that 50 prompts is a thin dataset; WER improvement may be modest for severe dysarthria (20–30% relative improvement expected, vs. 60–80% for mild accent adaptation). Voiceitt achieves strong results with 50–100 prompts [EVIDENCE src-008] but uses a purpose-built architecture; Whisper LoRA results on atypical speech are less well studied.

**Dependencies:** `peft>=0.10.0`, `transformers>=4.40.0` (for LoRA adapter loading). These are large packages (~500MB including model weights). Gate behind `pip install yazses[accessibility]` extra. The `faster-whisper` inference path cannot directly load PEFT adapters; a conversion step from HuggingFace Whisper → faster-whisper GGML format is needed post-merge.

**Risks:**
- PEFT LoRA on faster-whisper requires a round-trip through the HuggingFace `transformers` Whisper model for training, then re-export to CTranslate2 format for inference. This conversion is supported but adds complexity.
- 50 prompts may be insufficient for severe dysarthria. Provide a `--prompts 100` option and document expected improvement ranges.
- Enrollment audio quality depends on the recording environment; noisy enrollment degrades the adapter. Add SNR estimation and warn below threshold (SNR < 15dB).

## Success Metrics

- WER improvement on enrolled user's speech: ≥20% relative reduction for mild accent cases, ≥10% for dysarthria (measured on held-out 10% of enrollment audio).
- Enrollment wizard completion time: <10 minutes for 50 prompts.
- Adapter training time on a reference CPU (Intel i7-12th gen, 8 cores): <30 minutes.
- Adapter storage size: <15MB.
- Zero audio data leaves the local machine (verifiable by network monitoring during enrollment and training).
- `yazses adapt` succeeds on Python 3.11 with the `[accessibility]` extra on all three supported platforms.

## Evidence

- [EVIDENCE src-008] Voiceitt personalised offline recognition — demonstrates 50-prompt enrollment achieving significant WER improvement for atypical speech; validates enrollment corpus size and the local-only privacy model.
- [EVIDENCE src-009] PEFT/LoRA adaptation of speech models — shows rank-8 LoRA on encoder attention layers achieves strong personalisation with minimal compute and parameter overhead.
- [EVIDENCE src-005] faster-whisper CPU int8 inference pipeline — the production inference path that adapted weights must target.
