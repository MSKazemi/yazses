## Description

YazSes Remote enables hold-to-talk voice dictation inside SSH sessions, VS Code Remote SSH terminals, tmux panes, and mosh connections. The local daemon captures audio, transcribes it entirely on the local machine, then forwards only the resulting text across the SSH connection to a lightweight remote agent process. The remote agent receives plain text over a proxied UNIX socket and performs text injection on the remote host using whatever injector backend that host supports. No audio data crosses the network. The remote agent binary is a single self-contained Python process with no ASR dependency, weighing under 2 MB. A dedicated CLI subcommand manages the connection lifecycle and remote agent provisioning in a single step.

## User Pain

Remote developers, sysadmins, and data scientists who spend the majority of their working hours inside SSH sessions today receive zero benefit from YazSes. Their only alternatives are cloud-dependent solutions (Dragon for Mac, Whisper API) that require audio to leave the local machine, or manual clipboard copy-paste of transcripts. Developers using VS Code Remote SSH — the most popular remote development setup — have no voice dictation option that works inside the integrated terminal or editor. Sysadmins who connect to headless servers via tmux or mosh lose dictation entirely when switching to a remote context. This is a complete capability gap: voice is local-only today, and the SSH use case has no workaround.

## Proposed Solution

**Architecture:**

1. `yazses remote --host user@server [--port 2222] [--remote-socket /tmp/yazses-remote.sock]`
   - The CLI provisions the remote agent by copying a self-contained `yazses-agent` binary to the remote host via `scp` (or `rsync` for speed) on first run, caching it keyed by host fingerprint.
   - Opens an SSH control socket (`ssh -M -S ~/.ssh/yazses_ctl_%h`) plus a port forward: `ssh -L /tmp/yazses-fwd-<host>.sock:/tmp/yazses-remote.sock`.
   - Starts the remote agent: `ssh -S ctl_socket user@server yazses-agent --socket /tmp/yazses-remote.sock`.

2. **Local daemon change:** A new `RemoteInjectorBackend` in `src/yazses/inject/remote.py` connects to `/tmp/yazses-fwd-<host>.sock` and writes newline-delimited JSON-RPC `inject` calls, identical in format to the existing local IPC protocol.

3. **Remote agent** (`src/yazses/agent/remote_agent.py`): A minimal asyncio server. Reads JSON-RPC `inject` messages from the UNIX socket, selects the best available local injector (xdotool / ydotool / wtype / xclip), and performs the injection. No audio, no model, no heavy dependencies. Ships as a `yazses-agent` entry point in `pyproject.toml`.

4. **Session multiplexing:** Multiple simultaneous remote sessions are supported; each gets its own forwarded socket path keyed by `host:port`.

5. **VS Code Remote SSH integration:** The VS Code extension (future cap) can discover the forwarded socket automatically by checking for `/tmp/yazses-fwd-*.sock` and attaching.

**Config additions to `config.toml`:**
```toml
[remote]
default_host = "user@dev-server"
auto_provision = true
agent_cache_dir = "~/.cache/yazses/agents"
```

## Feasibility Notes

**Complexity:** Medium. SSH port forwarding is a well-understood primitive. The remote agent is intentionally thin — it reuses the existing `inject/` module wholesale, which already supports the target platforms. The main engineering work is the forwarding socket plumbing and the agent provisioning flow.

**Dependencies:** No new Python packages. Uses stdlib `asyncio`, `subprocess`, `pathlib`. SSH must be available on the local machine (universal assumption for the target persona). The remote host needs Python 3.11+ if running from source; the self-contained binary path requires PyInstaller.

**Risks:**
- SSH latency adds ~1-50ms round-trip overhead on LAN/VPN; acceptable since transcription already dominates at 200-800ms.
- Remote agent provisioning fails silently if the remote host lacks write access to `/tmp`; mitigated by configurable remote socket path and clear error messages from `yazses doctor --remote`.
- Windows SSH targets require a WinAPI injector on the remote side — defer to a follow-up; document as known limitation.
- mosh does not support general port forwarding; users must combine mosh with a separate `ssh -L` tunnel, which the CLI can open automatically.

## Success Metrics

- Latency from speech release to text appearing in remote terminal: median <800ms on LAN (same as local).
- Remote agent binary size: <3 MB standalone.
- `yazses remote --host user@server` succeeds from zero state (no prior provisioning) in <30 seconds on first run.
- Zero audio bytes transmitted over the SSH tunnel (verifiable with `tcpdump`/`wireshark` packet capture test).
- Works across all three supported local platforms (Linux, macOS, Windows WSL) to a Linux remote host.
- `yazses doctor --remote user@server` correctly diagnoses missing injector backends on the remote.
