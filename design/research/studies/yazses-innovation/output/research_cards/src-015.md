## Summary

A2-LLM (arXiv 2602.04913, 2026) presents an end-to-end model that jointly reasons over language, audio prosody, and 3D facial motion to drive conversational avatar behaviour from voice input. [EVIDENCE src-015] The pipeline achieves voice → intent → avatar action at approximately 180 ms end-to-end on GPU, demonstrating that LLM-level reasoning about user intent is compatible with interactive latency requirements for metaverse and avatar applications. [EVIDENCE src-015] The relevance to YazSes is indirect: this paper establishes the feasibility of real-time voice-driven avatar control and provides a latency reference point for the metaverse module concept.

## Key Findings

- **Joint reasoning:** A2-LLM jointly processes audio input (prosody, speech content) and language semantics in a single LLM forward pass, producing both a text response and 3D facial motion parameters. [EVIDENCE src-015] This eliminates the cascade latency of separate ASR → NLU → TTS → animation pipelines.
- **180 ms end-to-end on GPU:** The full pipeline (audio input → intent reasoning → avatar action output) runs at approximately 180 ms on GPU hardware. [EVIDENCE src-015] This meets the <200 ms XR real-time threshold established in src-014.
- **Prosody-aware intent:** By processing audio directly (not just transcribed text), A2-LLM captures prosodic cues (stress, pitch, pace) that carry semantic meaning independent of word content. [EVIDENCE src-015] A user saying "sure" with falling intonation vs. rising intonation conveys different intent.
- **3D facial motion output:** The model outputs avatar facial animation parameters (blend shapes, jaw movement) synchronised with speech content and prosody. [EVIDENCE src-015] This is relevant to YazSes metaverse module if avatar-synchronised voice output is in scope.
- **LLM reasoning + interactive latency:** The paper's primary contribution is demonstrating that LLM-scale reasoning is compatible with <200 ms interactive latency on GPU. [EVIDENCE src-015] This challenges the assumption that LLM involvement always implies unacceptably high latency.
- **GPU requirement:** The 180 ms figure is GPU-dependent. [EVIDENCE src-015] CPU inference would be substantially slower. [HYPOTHESIS]

## Gaps Surfaced

- **gap-a2llm-1:** The 180 ms latency is GPU-only; CPU inference latency is not reported. [EVIDENCE src-015] For YazSes's offline-CPU-first design, this architecture is currently impractical without a GPU. A quantised CPU path is needed before this approach is viable.
- **gap-a2llm-2:** A2-LLM processes audio + language jointly, requiring a fundamentally different architecture from YazSes's current separate ASR → inject pipeline. Adopting this approach would require significant architectural refactoring. [HYPOTHESIS]
- **gap-a2llm-3:** The paper evaluates conversational avatar behaviour, not text dictation or command dispatch. The mapping from A2-LLM's output space (avatar facial motion) to YazSes's output space (text injection + commands) is not trivial.
- **gap-a2llm-4:** Prosody processing requires raw audio input to the LLM, which conflicts with YazSes's VAD-gated, chunk-based audio handling. Continuous audio streaming to a GPU-resident LLM is a different operational model.
