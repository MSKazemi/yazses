## Source Summary

This December 2024 arXiv preprint proposes an adaptive hybrid architecture for speech-to-action systems that dynamically routes inference between a cloud-hosted large LLM (GPT-3.5-turbo) and an edge-deployed small LLM (TinyLlama-1.1B-chat-v1.0, 4-bit quantised). The routing decision is made per utterance based on estimated task complexity and connectivity status. The paper addresses the fundamental privacy/latency tradeoff: cloud LLMs offer better intent resolution but incur network latency and send user audio off-device; edge LLMs preserve privacy and work offline but have lower intent accuracy. The adaptive approach dynamically falls back to the edge model when offline or when the utterance is classified as low-complexity.

---

## Key Claims

- [EVIDENCE src-003] GPT-3.5-turbo is used for online inference (cloud); TinyLlama-1.1B-chat-v1.0 for offline inference (edge). Both operate on the same ASR transcript from a shared speech front-end.
- [EVIDENCE src-003] The system explicitly addresses the tradeoff: cloud = strong LLM + high latency + privacy risk; edge = limited accuracy + low latency + offline-capable.
- [HYPOTHESIS] TinyLlama-1.1B at 4-bit quantisation (~700 MB model) can run on a modern laptop CPU at 15–30 tokens/second, giving an intent routing decision in 100–300 ms for typical short utterances — acceptable for interactive use if the routing classifier is fast.
- [EVIDENCE src-003] The routing decision uses a lightweight complexity classifier to determine which model to invoke, avoiding the latency of always hitting the cloud.
- [HYPOTHESIS] For YazSes, the "connectivity" trigger in this architecture maps cleanly to a user preference flag (always-offline vs. hybrid) rather than automatic detection — users of a privacy-first voice daemon will prefer the explicit choice.
- [EVIDENCE src-003] The edge model (TinyLlama) handles "low-complexity" speech-to-action mappings adequately for the paper's task set, with quality degradation mainly on multi-step reasoning and rare intents.

## Technical Mechanisms

### Architecture / System Design

[EVIDENCE src-003] The pipeline is: Microphone → ASR (shared) → Transcript → Complexity Classifier → Route to {TinyLlama (edge) | GPT-3.5 (cloud)} → Action execution. The complexity classifier is a lightweight binary classifier (not a full LLM) trained on intent type and utterance length features. The action execution layer maps LLM output to OS or application commands.

### Core Algorithms or Methods

[EVIDENCE src-003] Intent routing uses a learned binary classifier (low vs. high complexity) operating on shallow features of the ASR transcript. [HYPOTHESIS] For YazSes, the classifier could be rule-based initially (utterance length < N tokens and matches known grammar patterns → local; otherwise → local SLM or queue for later cloud batch) since YazSes already has a grammar classifier that handles common intents.

### Key Data Structures or APIs

[EVIDENCE src-003] The system output is a structured action schema (verb + target + parameters) rather than free text. [HYPOTHESIS] This aligns with YazSes' existing CommandIntent dataclass — the LLM would produce a structured intent that is passed to the existing dispatch.py rather than raw text injection.

## Identified Gaps

### Stated Limitations

- [EVIDENCE src-003] The paper evaluates on a limited task set; generalization to open-domain coding or creative writing tasks is not demonstrated.
- [EVIDENCE src-003] TinyLlama's performance on complex multi-step instructions is significantly below GPT-3.5; the accuracy gap for rare or technical intents is not quantified.

### Inferred Gaps

- [HYPOTHESIS] The paper does not address voice injection security — an adversary embedding commands in audio that the LLM would execute as OS actions. This is critical for any system that maps voice to arbitrary OS commands.
- [HYPOTHESIS] No evaluation of the approach with code-specific intent vocabularies (IDE commands, shell commands, variable names) is provided.

### Evaluation / Coverage Gaps

- [EVIDENCE src-003] Only action-execution accuracy is measured; no latency breakdown is provided per component, making it hard to isolate ASR vs. LLM inference vs. routing overhead.

## Applicability to Project

[EVIDENCE src-003] The adaptive edge-cloud routing architecture is directly applicable to YazSes v0.4 design. YazSes already has an offline-first architecture; adding a local SLM (e.g., TinyLlama or Phi-3-mini) as the intent routing layer, with the existing grammar classifier as a fast pre-filter, matches this paper's architecture pattern. [HYPOTHESIS] YazSes can implement the three-tier routing: (1) grammar regex match → immediate dispatch; (2) local SLM → semantic dispatch; (3) optional cloud API → complex multi-step tasks, with user-controlled tier ceiling.

[EVIDENCE src-003] The paper validates that 1B-parameter quantised models are sufficient for low-complexity speech-to-action mapping. YazSes' existing command vocabulary (28 intents, mostly single-action) falls into the low-complexity category where TinyLlama-class models achieve acceptable accuracy. [HYPOTHESIS] This means YazSes can offer LLM-powered semantic commands without requiring a GPU, which is essential for the CPU-only, offline-first user base.
