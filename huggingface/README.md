# huggingface/ — what YazSes publishes on the Hugging Face Hub

This directory holds the sources of YazSes's public Hugging Face presence, and
`manifest.json`, the single list of what may ever be uploaded. Nothing here is uploaded
unless the manifest names it, the owner has approved it, and the publish workflow runs.

## Layout

| Directory | Hub destination | Manifest name |
|---|---|---|
| `organization/` | Space `yazses/README` (the organisation card) | `org-card` |
| `showcase/` | static Space `mskazemi/yazses-showcase` | `showcase` |
| `benchmarks/` | dataset `mskazemi/yazses-benchmark-results`, generated by `scripts/export_hf_benchmarks.py` | `benchmarks` |
| `space-demo/` | existing Space `mskazemi/yazses-offline-transcription-demo` | `demo-space` |
| `manifest.json` | the allowlist, the approval flags and the Collection definition | — |

## The public/private rule

Only the files listed under a destination's `files` are ever uploaded. Everything else in
this repository stays where it is, in particular:

- never the private manuscript tree wholesale (the public benchmark harness is exported
  through `scripts/export_hf_benchmarks.py`, not copied);
- never the design records, the coding-agent directory, or the strategy tree;
- never PDFs, audio or video (a tiny synthetic fixture must be named in the manifest),
  keys, databases, dotfiles, or anything containing a token, a private key, or a home path.

`scripts/hf_preflight.py` enforces this offline and read-only. It cannot publish: it
imports nothing that talks to the Hub, and a test asserts that.

## Everyday commands (all offline, nothing is uploaded)

```sh
uv run python scripts/hf_preflight.py --print-plan          # validate, list file -> repo
uv run python scripts/hf_preflight.py --select showcase     # one destination
uv run python scripts/hf_collection.py --offline            # Collection plan, no network
uv run python scripts/hf_collection.py                      # Collection diff, anonymous read
```

`hf_collection.py --apply` is the only command that changes the Hub from a laptop, and it
refuses to run unless `collection.owner_approved` is true and you are logged in.

## Publishing

The only thing that uploads is `.github/workflows/huggingface-publish.yml`, a manual
`workflow_dispatch` run from `main`. It validates first, then, if `dry_run` is unticked,
uploads exactly the allowlisted files of one destination using Hugging Face
[Trusted Publishers](https://huggingface.co/docs/hub/trusted-publishers): a short-lived,
single-repository token obtained from the job's OIDC identity. There is no stored token.
Remote files are never deleted.

To bring a destination live (owner steps):

1. Create the Hub organisation and the empty repository named in the manifest.
2. On the repository's Settings, Trusted Publishers, add a GitHub Actions publisher:
   repository equals `MSKazemi/yazses`, ref equals `refs/heads/main`, workflow_ref starts with
   `MSKazemi/yazses/.github/workflows/huggingface-publish.yml@` (the claims as the Hub's form shows them).
3. In GitHub, put a required reviewer on the `huggingface-publish` environment.
4. In `manifest.json`, set that destination to `"status": "live"` and
   `"owner_approved": true`, record its verified `url`, and merge the change.
5. Run the workflow with `dry_run` unticked.

A URL is recorded in the manifest only after the resource has been seen to exist. Planned
resources keep `"url": null` and are skipped by the Collection script until they are live.
